1. Introduction

PinForge AI ("the Application") is a content automation tool operated by Zoubire. It runs locally on the operator's own computer and helps turn digital products from a Gumroad store into Pinterest Pins: it imports product information, analyzes products with AI, generates Pinterest SEO titles, descriptions and keywords, generates images, and publishes Pins through the official Pinterest API when the operator chooses to do so.

This policy describes what information the Application accesses, how it is used, where it is stored, and the choices available to you. It covers only what the Application actually does, as described below.

2. Information We Access

The Application may access the following categories of information:

  • Publicly available product information from a Gumroad store (see Section 3).
  • Pinterest account information, boards, and Pins from the single Pinterest account that explicitly authorizes the Application through Pinterest OAuth (see Section 4).
  • Content the operator creates inside the Application, such as generated titles, descriptions, keywords, image prompts, images, publishing queues, scheduler jobs, and application logs.

The Application does not collect analytics about its operator, does not include third-party tracking, and does not access information beyond what is listed in this policy.

3. Gumroad Product Information

PinForge AI may process publicly available product information from the Gumroad store at https://zoubire.gumroad.com. This can include:

  • Product name
  • Product description
  • Price
  • Product URL (permalink)
  • Product images / thumbnails
  • Other publicly available product metadata such as tags

The Application reads only information that is publicly visible on the store pages (or that the operator imports manually, e.g. via CSV). It does not access private Gumroad customer data, buyer identities, order histories, or payment information.

4. Pinterest Information

PinForge AI can connect to a Pinterest account through Pinterest OAuth. PinForge AI only accesses Pinterest data from the account that explicitly authorizes the application.

When authorized by that account, the Application may access:

  • Pinterest account authorization information
  • Pinterest boards (including board IDs and names)
  • Pinterest Pins (including Pin IDs, titles, and descriptions where needed)
  • OAuth access and refresh tokens required to authenticate API requests

These permissions are used to:

  • Read the user's boards
  • Create boards when authorized
  • Read Pins when necessary
  • Create Pins
  • Prevent duplicate publishing
  • Schedule and publish content

The Application requests only the scopes it needs (boards:read, boards:write, pins:read, pins:write). It does not claim access to all Pinterest users and does not request private information beyond what these permissions provide.

5. How Information Is Used

Information accessed by the Application is used to:

  • Display the operator's Gumroad products inside the Application.
  • Analyze products and generate Pinterest SEO content and image prompts.
  • Generate, preview, queue, schedule, and publish Pinterest Pins.
  • Read boards and Pins to support publishing and avoid duplicates.
  • Maintain the local publishing queue, scheduler jobs, and logs.

Information is not used for advertising, profiling, or any purpose unrelated to operating PinForge AI for its operator.

6. AI Processing

Local AI. The Application can use AI software running on the operator's own computer, such as Ollama for text generation and ComfyUI for image generation. When configured this way, AI processing happens locally on the operator's machine.

Optional external AI. If the operator deliberately configures an external AI or image provider, the information needed to perform the requested generation may be transmitted to that provider. Using an external provider is optional and is never required to run the Application's core features.

7. Local Storage

PinForge AI is designed as a local application. Data is stored on the operator's own computer and may include:

  • Product metadata
  • Generated AI text (analyses, titles, descriptions, keywords, prompts)
  • Generated images
  • Publishing queues and scheduler jobs
  • Application logs
  • Pinterest authentication information and tokens

The operator controls the local machine and can delete local application data at any time (see Section 11).

8. Data Sharing

PinForge AI does not sell personal information.

Data may be transmitted to:

  • Pinterest, when using Pinterest API functionality (e.g. reading boards, creating Pins);
  • Optional external AI providers, if the operator configures them;
  • Other optional services explicitly enabled by the operator.

Apart from these functional transmissions initiated by the operator, the Application does not share data with third parties.

9. Data Retention

Local application data is retained on the operator's computer until the operator deletes it. The Application does not automatically delete data after a fixed period. Pinterest OAuth tokens remain stored locally until the operator disconnects the Pinterest account or deletes the data.

10. Pinterest Authentication

Pinterest access uses the official Pinterest OAuth 2.0 authorization-code flow. The operator signs in on Pinterest's own website, approves the requested scopes, and Pinterest returns an authorization code that the Application exchanges for access and refresh tokens. Tokens are kept in the Application's server-side local storage and are not exposed to the browser interface. If a token expires, the Application attempts to refresh it; if refresh is not possible, the operator is asked to reconnect.

11. Data Deletion

To remove local PinForge data, the operator can delete Pins, products, queue entries, generated images, logs, and database records from inside the Application or by deleting the Application's local data directory. Disconnecting the Pinterest account inside the Application removes the locally stored Pinterest tokens.

To revoke the Application's authorization on Pinterest's side, the user can remove PinForge AI's access in their Pinterest account settings. Revoking access stops future API access but does not automatically delete Pins that were already published to Pinterest; published Pins must be deleted on Pinterest itself.

There is no remote deletion mechanism beyond what is described here.

12. Security

The Application is designed to:

  • Keep API secrets and tokens server-side rather than exposing them to the frontend.
  • Avoid logging sensitive access tokens.
  • Keep credentials in environment configuration that is never committed to source control.
  • Validate incoming API data.

Because PinForge AI runs on the operator's own computer, local security also depends partly on the security of that computer and operating system (e.g. device access controls, OS updates, and disk encryption).

13. Children's Privacy

PinForge AI is a technical tool for the operator's own content workflow and is not directed at children. It is not designed to collect information from children.
